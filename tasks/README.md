# 任务文件夹（tasks/）使用说明

本仓库的任务管理采用「拆文件」方式：`LEARNING_PLAN.md` 只保留状态、索引、日志与速查，详细任务卡按任务单独成文件，控制每次开工的上下文消耗。

## 分工

- `LEARNING_PLAN.md`：唯一入口（当前状态 + 任务索引 + 关键决策 + 开发日志 + 报错速查）
- `tasks/README.md`：本文件，目录说明 + 通用审查清单
- `tasks/T7-*.md` 等：单任务卡（新任务继续按此格式新增）
- `tasks/blue-archive/`：设计稿落地（蔚蓝档案主题）任务组，含 T-D1 ~ T-D10

## 开工读取规则

1. 先读 `LEARNING_PLAN.md` 的「当前状态」和「开发日志」
2. 只读「当前任务」对应的任务卡，没有必要时不读其他任务卡
3. 完成一个任务后：按任务卡「完成标志」验收 → 过下面通用审查清单 → 更新主文档状态 → 提交（是否推送按用户要求）

## 任务卡格式

每张任务卡固定包含：目标 / 前置条件与涉及文件 / 步骤 / 完成标志 / 审查重点 / 本任务概念。

## 通用审查清单（每个任务完成后必过）

1. `npm run type-check`、`npm run lint`、`npm run build` 全部通过
2. `npm run dev` 目测：功能、布局、路由跳转与设计稿一致
3. 死链接 / 路由失效：所有 `<RouterLink>`、`router.push`、`<a href>` 目标存在
4. 垃圾清理：未使用文件、空壳组件、注释掉的代码、临时文件
5. 样式复用：相同样式进全局 `main.css`，页面内不重复造轮子
6. 数据解耦：页面不直接写死数据，统一走数据入口（`src/data/` 或 `src/api/`）
7. 组件可复用：公共部件（卡片、分页、筛选条）放 `src/components/`，props/emits 定义清楚
8. 无魔法值乱飞：颜色、间距、断点尽量用 CSS 变量与统一数值

发现问题当场修复，不留待办进下一个任务。
